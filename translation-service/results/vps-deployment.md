# VPS 部署与性能实测（2026-11-16）

服务已部署到 `root@64.177.59.175` 的 `/opt/tubitle-translation`，公网地址为 **https://translate.yzdev.de5.net**。当前运行小牛 `lmt-60-0.6b-q4`，同机已准备 Hy-MT2 Q4，可随时切换。本次没有在 VPS 安装 2-bit、SMaLL-100、OPUS 的模型或运行环境。

## 硬件与配置

- Ubuntu 26.10，Linux x86_64；AMD EPYC-Genoa，4 vCPU（虚拟拓扑显示 2 核 × 2 线程），系统识别内存 7,775,965,184 字节，约 7.24 GiB；根分区约 70 GB。
- llama.cpp 固定 b12140，从源码编译 CPU 版本，开启本机指令集优化，GPU 层数 0；Node.js 24.19.0。
- 推理线程 4、并行槽位 4、总上下文 8192。小牛采用 Q4_K_M、贪心解码；混元沿用原有采样配置。两者不是同参数模型，比较的是实际服务配置。
- 两个权重均通过 SHA-256 校验，小牛与之前 Mac 上测试的是同一 GGUF 文件。

## VPS 内部 HTTP 性能

沿用同一套 16 条输入：8 条英文短字幕、4 条英文段落、英译日/西/阿及中译英各 1 条。每组先预热并检查 16 条译文；短字幕在并发 1/2/4 各 32 次，段落在每档各 16 次。共 288 次计时请求及 32 次质量检查，全部 HTTP 200 且 finishReason=stop。请求关闭提示缓存，串行测试不同模型。

每个表格单元为 **条/秒 / P95 毫秒**：

| 模型 / 输入 | 并发 1 | 并发 2 | 并发 4 |
|---|---:|---:|---:|
| 小牛 Q4 / 短字幕 | 4.29 / 307 | 4.65 / 608 | 5.24 / 1118 |
| 小牛 Q4 / 段落 | 1.27 / 901 | 1.42 / 1560 | 1.68 / 3012 |
| Hy-MT2 Q4 / 短字幕 | 1.66 / 1095 | 2.02 / 1401 | 2.18 / 2501 |
| Hy-MT2 Q4 / 段落 | 0.62 / 1815 | 0.68 / 3219 | 0.77 / 6766 |

并发 4 的短字幕，小牛吞吐约为混元 Q4 的 **2.40 倍**；段落约 **2.18 倍**。本轮每档只有 16 或 32 次请求，P95 仅用于比较这组输入，不能当作长期服务保证。

## 小牛持续负载与多核使用

另在 VPS 本机执行并发 4、目标持续 60 秒的短字幕测试（最后一批完成后才结束）：

- 实际 60.492 秒，共 299 条，失败 0 条。
- 吞吐 **4.94 条/秒**；P50 **742 ms**；P95 **1118 ms**。
- 服务 cgroup 平均 CPU **391.0%**，以单核 100% 计；折合四核总容量 **97.7%**，已基本使用全部 4 vCPU。
- 每秒采样到的服务 cgroup 最大内存 **1,342,074,880 字节，约 1.25 GiB**。

验收时小牛推理进程 RSS 为 1,727,340 KiB（约 1.65 GiB），另有两个 Node 进程；整机 available 约 5.4 GiB，swap 使用为 0。

这里的内存是 systemd cgroup 的 memory.current 计账，**不是整机内存，也不等于进程 RSS**；模型文件页可能记在其他 cgroup 的页缓存中。不要据此认为 1.25 GiB 就是部署所需全部内存。Q4 本轮 systemd MemoryPeak 约 1.43 GiB，但 pidstat 曾记录推理进程 RSS 约 2.43 GiB，计账范围不同，不能直接相加或等同。

结论：4 vCPU / 8 GB 足够运行单个当前模型并供小规模体验；持续负载首先遇到 CPU 瓶颈。增加 RAM 通常不会让这套纯 CPU 推理明显提速。测到的约 5 条/秒是容量上沿，实际运行应预留余量；尚未做长时压力测试或按 1,000 用户真实字幕流测试，不应视为已能承载那个规模。

## 用户电脑到公网 HTTPS 的延迟

从本机 Mac 使用系统 curl、默认可信证书验证及访问密钥调用正式域名。每档 8 条短字幕，分别测并发 1/4；每个请求新建 curl/TLS 连接，不等同于浏览器复用连接的性能。

| 并发 | 成功 | 条/秒 | P50 毫秒 | P95 毫秒 |
|---|---:|---:|---:|---:|
| 1 | 8/8 | 0.41 | 1721 | 4376 |
| 4 | 8/8 | 0.89 | 1970 | 6916 |

这些数字包含 DNS、TLS、网络、代理路径和推理时间。本机正常 DNS 返回 198.18.* 虚拟地址，可见存在虚拟 DNS/代理路径；固定实际 VPS IP、仍验证原域名证书的健康检查也出现约 4 秒总耗时。公网尾延迟明显高于 VPS 内部，不能用它反推模型算力。仅 8 条样例时 P95 等于最大值，后续应在实际观看网络上评估字幕预取体验。

## 译文质量

小牛在 VPS 的关键例子与 Mac 一致：能正确区分“3 个百分点”和“3%”，但把“My coffee kicked in right after I decided to take a nap.”译为“我决定睡个觉后，咖啡就冲到了我嘴里。”混元 Q4 在这条更准确。若以翻译质量为先，可以切回 Q4；默认小牛是本次部署对吞吐的选择，并不意味着其质量超过混元。

## 已验证的部署行为

- 服务以专用 `tubitle` 账户运行，systemd 开机自启、异常退出自动重启，API 与推理进程同一生命周期。
- 强制 SIGKILL 推理进程，约 **7.04 秒**后新服务进程就绪；随后验证手动停止不会被健康检查重新拉起，最终恢复小牛。
- 每分钟请求一次内部 `/health`，连续三次失败触发重启；服务退出由 systemd 直接处理。健康检查只判断模型接口是否可用，不代表翻译质量正确。
- 尚未接邮件、微信或其他外部告警渠道；故障会记录在 journal，自动恢复已验证。整台 VPS 掉线需要另外配置外部监测。
- Nginx HTTPS 入口、Bearer 访问密钥、请求体上限、全局/单 IP 频率及同时处理请求数限制已配置；缺失和错误密钥均实测返回 401。`/health` 为无需密钥的公共健康接口，带限速。
- UFW 保留 SSH 22，只新增 80/443；18080/18081 仅监听 127.0.0.1。
- Let's Encrypt 正式证书有效至 **2027-02-14**，certbot 定时续期与续期后 Nginx reload hook 已启用；未额外运行续期 dry-run。
- 插件新增服务地址和访问密钥设置，保留默认本机地址；仅允许远程 HTTPS；模型发现、翻译请求使用同一地址和密钥，缓存按服务地址与模型区分。112 项插件测试、TypeScript 检查与构建通过；VPS 上 3 项模型适配测试通过。尚未在浏览器中整段观看视频。
